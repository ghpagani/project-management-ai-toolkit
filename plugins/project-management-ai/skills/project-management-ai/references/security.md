# Security boundary / Limite de segurança

The preview handles synthetic and explicitly authorized public datasets only. A classification field, opaque IDs, instructions and schema checks cannot detect all sensitive values or prevent a host model from transmitting them. Local Python does not imply a local LLM. No network calls are implemented by the engine; OS-level isolation and egress denial must be enforced independently. No telemetry, external APIs, credentials, plugins requiring permissions, background jobs, connectors or automatic Git operations in the engine.

Use a private, access-controlled workspace outside source trees. Prevent other users from changing parent directories; the CLI does not defend against malicious local users, directory junctions, races in hostile filesystems or compromised runtimes. Windows ACLs, disk encryption, backups, retention, audit logging, DLP and egress policies are host responsibilities. Temporary files may remain after a crash. Do not assume deletion is secure erasure. Reports and metadata can be sensitive. Never use real data in CI, cloud chats or public repositories. Reject documents with instructions; never execute them. Escalate any accidental disclosure through the approved institutional incident process.

Before any institutional use, security/privacy/IT approval, threat modeling, data-flow mapping, vendor and residency assessment, least privilege, tenant isolation, DLP, egress tests and independent penetration testing are mandatory. This preview has no institutional approval and no 100% security guarantee.
